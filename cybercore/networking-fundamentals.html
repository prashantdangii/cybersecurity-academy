    Layers that matter

    Concept

    You don't debug "the internet." You debug which layer failed — name, port, route, or cable.

    L7ApplicationHTTP · DNS · TLS · SSH
    L4TransportTCP · UDP · ports
    L3NetworkIP · ICMP · routing
    L2Data linkMAC · ARP · Ethernet
    L1Physicalcable · Wi‑Fi · NIC
    TCP/IPmodel you actually use
    5layers worth memorizing
    L7where most vulns live

    Symptom

    • Site loads forever → often DNS or TCP
    • Connection refused → port closed / no listener
    • Timeout → filter, blackhole, or no route

    First question

    • Did the name resolve?
    • Is the port open from here?
    • Do I have a route to that IP?

    Check yourself

    curl returns "Could not resolve host". Which layer broke first?

    Your host on the wire

    Concept

    Every box needs an IP (L3), a MAC (L2), and usually a default gateway to leave the LAN.

    • IP — where routers send packets
    • MAC — where switches forward frames
    • Gateway — first hop off your subnet
    • ARP — IP → MAC on the local segment
    Appwants 1.2.3.4:443
    Routevia gateway 10.0.0.1
    ARPresolve gateway MAC
    Frameout eth0 / wlan0

    Subnets & CIDR

    Concept

    CIDR says how many bits are network vs host. Same network bits → same LAN → no router needed.

    /24256 addrs · common LAN
    /1665k · big private
    /32one host
    /0default route
    AddressMeaningAttack note
    10.0.0.0/8Private (RFC1918)Internal recon goldmine
    172.16.0.0/12PrivateCommon in corp / cloud VPC
    192.168.0.0/16PrivateHome / small office
    127.0.0.1LoopbackLocal-only services
    Quick math

    10.0.5.20/24 → network 10.0.5.0, broadcast 10.0.5.255, usable .1–.254. Host 10.0.6.8 is a different subnet.

    04concept · terminal · lab

    TCP, UDP & ports

    Concept

    Port = which process on the IP. TCP is reliable + ordered; UDP is fire-and-forget (DNS, many games, VPN).

    SYNclient opens
    SYN-ACKserver accepts
    ACKsession up
    RST / timeoutclosed or filtered
    • 22 SSH
    • 53 DNS
    • 80 HTTP
    • 443 HTTPS
    • 445 SMB
    • 3389 RDP
    • 8080 alt HTTP

    05concept · terminal · lab

    DNS in practice

    Concept

    DNS maps names → data. Attackers enumerate it; defenders monitor it. Always ask: which resolver answered?

    AIPv4
    AAAAIPv6
    CNAMEalias
    MXmail
    TXTSPF · verify
    NSauthoritative

    Offense uses

    • Subdomain discovery
    • Zone transfer attempts (AXFR)
    • TXT / MX for org intel

    Defense watches

    • Odd query volumes
    • DNS tunneling patterns
    • Hijacked NS records

    HTTP path & curl

    Concept

    After TCP (and usually TLS), the client speaks HTTP: method, path, headers, body. Status codes tell you what happened.

    200OK
    301/302redirect
    401/403auth / forbid
    500server error
    DNSname → IP
    TCP/TLS:443 session
    HTTPGET /path
    Responsestatus + headers + body

    07concept · terminal · lab

    Reachability & routes

    Concept

    ping (ICMP) tests reachability. traceroute shows hops. Silence ≠ “host down” — ICMP is often filtered.

    Don't assume

    • No ping reply ⇒ host is dead
    • traceroute * * * ⇒ attack failed
    • One path forever (ECMP/VPN)

    Do instead

    • Test the real port (TCP/HTTP)
    • Compare from another network
    • Check local route + DNS first

    Mission terminal

    MissionTrace path to lab.targetping -c 3 then traceroute (or tracert on Windows).
    bash · pathlive
    lab@net:~$

    • Ping lab.target (ping -c 3 lab.target)
    • Traceroute (traceroute lab.target)
    ping -c 4 1.1.1.1
traceroute 1.1.1.1
# macOS: traceroute · Windows: tracert · Linux: traceroute or mtr

    08concept · command · lab

    Packets & capture

    Concept

    When logs lie, packets don't. tcpdump/Wireshark show the real handshake, SNI, and payloads (if not encrypted).

    Capturetcpdump -i any
    Filterport 443 or host …
    ReadSYN · data · FIN
    Decidedrop · malware · misconfig
    • pcap — saved capture file
    • BPF — capture filter language
    • SNI — hostname in TLS ClientHello
    • Wireshark — GUI for deep analysis

    Command

    # needs permission; own lab only
sudo tcpdump -i any -nn port 53
sudo tcpdump -i eth0 -nn host 10.0.0.5 and port 80 -w http.pcap
# read later
tcpdump -nn -r http.pcap | head
# Wireshark: File → Open http.pcap · filter http || dns
